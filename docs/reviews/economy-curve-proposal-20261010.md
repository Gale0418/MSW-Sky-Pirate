## 設計目標與已知基線

主人已定案的是 T5 金幣造價 2,147,483,647 G；T2–T4 船價只曾是本附件研究候選，並非主人指定，且已由主整合草案取代。現行四艘 50,000 G 的船都是不同定位的 T1，不能視為 T1–T4。造船材料另計，T5 金幣價不含材料，也不可將材料費硬湊成 T5 金幣造價。

現有 T1 三層耐久總和 192 點，普通 T1 三層全修 9,600 G；森芽號因船體上限 +20%，全修 10,800 G。T0 免費修理。玩家起始資金 12,000 G。現行普通敵全為 120 HP、每 2 秒攻擊一次，攻擊值 8–16；伺服器每秒自動炮擊 20×cannonMultiplier，沒有彈藥扣款。當前單敵約 7.6 秒戰鬥僅是現狀推估，不能拿來承諾未來每小時擊殺數。

依先前盤點，ProfileStore 和交易驗證 moneyMax 是 2,147,483,647。這只是現行程式檢核界線；本草案不宣稱任何 MSW/mLua 64-bit 支援。T5 金額等於現行 ProfileStore／交易驗證上限；玩家餘額剛好等於上限時可支付該筆 T5 造價，並非因此買不到。真正需要處理的是超出上限的存款準備金、賞金加總、交易報價／總額及存檔讀回；不得先加後溢位或錯誤 clamp。此為程式驗證上限，不是 MSW/mLua 原生位寬結論。

### FIFO 舊成本相容規則

現有貨艙 lot 保存 good id、quantity、buyPrice，賣出依 FIFO 批次成本計算。調整目錄 price 時，禁止重寫已存 lot 的 buyPrice、合併不同成本批次、以新目錄價回填舊貨成本，或把市價壓力直接套回成本欄位。商品報價應帶有凍結的 priceVersion；版本切換只影響新報價／新購 lot，不重算已存在的舊報價或 lot。舊 lot 繼續以購入時 buyPrice 計損益。若需要遷移舊 profile，缺少 lots 的舊格式只能沿用原 scalar buyPrice 相容投影，不能猜算新價。配方消耗舊貨時應以實際扣除的 FIFO lot 記錄成本，配方 UI 的新參考價只作估值，不應覆寫存檔成本。

### 現有暴利與材料定價的牽動

黑暗塔奇昂現值基價 250,000 G/件，8 件購入約 2m、初始壓力下售往納希約 5.55m，估算交易毛利約 3.55m（未扣航程、修理與失敗成本）。Boss stock 每商品每帳號每 3 小時 1–10 件，市場壓力容量 10、恢復 8 小時，仍可能讓單次成功大單大幅提前存款。避免用純存款時數保證通關進度；主整合草案改以指定跨區 BOSS 戰利品作自然門檻。材料配方仍應依實際來源與凍結報價版本計價，不能把市場需求倍率當成造船單價。

## 收益公式與高額黑暗塔奇昂套利

分開記現金流與經濟損益，避免同一批貨購入及遺失成本重複扣除。

cashFlow = 實收貨物銷售 + 賞金現金 − 實付購入 − 修理費 − 消耗品費。
economicProfit = 貨物銷售 − 已售 FIFO 批次成本 − 遺失 FIFO 批次成本 + 賞金 − 修理費 − 消耗品費。

購入成本只進現金流；經濟損益按已售或遺失的 FIFO 批次成本認列，不能再把已付購入額和同批貨物遺失成本一起扣。未兌現素材另以凍結估值列示，不算現金收入。

必須正面處理黑暗塔奇昂：舊審核依現行報價公式推算，8 件成本約 2,000,000 G，未受壓力且賣往納希時收入約 5,550,000 G，毛利約 3,550,000 G。這不是穩定每趟收入：貨架需抽中，Boss 商品帳戶庫存每商品每 3 小時 1–10 件，價格壓力容量 10、恢復 8 小時，8 件批次會顯著壓低同商品後續報價；航程、修理、失敗與實際可買量也未扣除。因此不能只靠存錢時間保證升級節奏；高階購買條件應依主整合草案指定的跨區 BOSS 戰利品自然門檻，不採固定航行趟數門檻。

主整合草案以指定跨區 BOSS 戰利品作為自然解鎖條件，不採固定 8／25／60／120 航次門檻；單純完成趟數可能只需幾分鐘，不能代表長期進度。仍允許富豪引怪並在存活後取得高收益，不設每日收入上限或個人賞金遞減。

「沉船已得獎勵是否保留」必須定為單一規則：若保留，失敗結算須先把已 claim 戰利品原子寫入 profile，再扣除貨物／修理；若不保留，戰利品不得先進可花用 profile 餘額，避免抵港與沉船雙領。不要讓同一 kill claim 先加一次，沉船重播又加一次。

## 依賴與調參條件

- 航程遭遇公式要依路段長度與空域風險抽選；每張 lure、stealth、fog、monster_bait、magic_resonator 只在對應 modifier 欄位讀取一次，不能同時放大出現率、總數及單隻賞金。船級與持有財富增加遭遇率、總敵數／強度；沒有炮或低火力不能降低難度。
- 怪物 threat rank、普通／菁英／BOSS 的空域池、精確出現率、波次、逃跑與沉船結算皆未實作；賞金數值必須在有實際存活、修理、失敗與每小時成交資料後平衡。本附件沒有實測通關時數。
- T5 目標值正好等於現行 ProfileStore / 交易驗證上限。任何造價、賞金及市場合計的新增實作都依賴貨幣欄位／RPC／序列化全流程安全驗證；在沒有證據前不宣稱 MSW/mLua 支援 64-bit 整數。餘額恰等於 2,147,483,647 G 時，購買同額 T5 可使支付後餘額歸零；需要在 max 以下保留餘額或將一次賞金／交易加總推過 max 時，才需調整貨幣範圍或採安全溢位處理。
- 市場商品貨架抽選、壓力與 Boss 庫存可能令一趟大單收入高度離散；上表淨收益目標只能用長期平均測試。必須單獨監控黑暗塔奇昂每帳號每 3 小時能買到幾件、8 件實際報價、庫存重置與「賣出—重買—重登」壓力有無重置漏洞。
- 若跨區 BOSS 戰利品作解鎖條件，需在造船廠交易驗證端檢查，而非只隱藏 UI 購買按鈕。身故／沉船的物品、現金、修理和 claim ledger 也需同一 profile CAS 規則，否則數值方案會被交易重放漏洞破壞。


## 整數金額與單次捨入規則

所有船價、卡片價、賞金、單價、數量乘算及 profile 餘額均以整數 G 設計；船／卡價優先採千或萬的整數倍，唯一指定的精確例外是 T5 = 2,147,483,647 G。不可用小數 G 存檔，也不可在每次乘數步驟都先捨入，否則會累積偏差與多次買賣套利。

建議在伺服器交易結算時保留中間精度，只在最終可結算單位套用一條規則：出售／折售與賞金使用 floor（向下取整至整 G；本方案賞金本身已是整數），避免多付一枚 G；修理費使用 ceil（向上取整至整 G），避免小額傷害被算成免費。單筆貨物價格先算未捨入的單位價，再 floor 到整 G 後乘整數件數；不要對商品基價、需求倍率、壓力倍率、件數各自重複取整。船價以整數金幣造價記錄；材料成本另列，不得為湊總價而併入 T5 的 2,147,483,647 G 金幣造價。交易批次總額按最終單位成交價逐件加總；賞金按固定整數單價乘結算擊殺數，只有同一 kill claim 可領一次。
