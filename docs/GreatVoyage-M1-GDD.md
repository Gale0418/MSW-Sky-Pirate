# Great Voyage M1 GDD

## 1. 一行概念

玩家在四個港口探索、靠船啟航，在官方世界圖選定目的港後沿唯一的直線穿越不同空域並完成跨港交易。2026-10-02 依主人授權停用全部舊航行事件，先完成船艙管理、五船購買換船及 T1 三槽改裝，再接短自動空戰；航程基準可調，船型與改裝以倍率作用，HUD 顯示百分比。

## 2. 關鍵決策

| 決策 | M1 定案 |
| --- | --- |
| 地圖型別 | 四張港口地圖與飛船甲板維持 `TileMapMode=0` MapleTile；動態角色使用 `RigidbodyComponent`／Foothold。 |
| 範圍 | 魔法森林、天空之城、玩具城、納希沙漠四港；直線多空域航圖、地方商品價差、百分比航程、五船買換與三槽改裝。舊遭遇停用，短自動空戰另驗。 |
| 資料真實來源 | 港口、貨物、航線與可用狀態以既有資料結構為基礎；內容擴展應逐步轉向 UserDataSet/CSV，避免把平衡散落在腳本。 |
| UI | 沿用既有 HUD 與 UUID；`.ui` 只透過 UIBuilder，UI 邏輯為 client-only。 |
| 驗收 | Maker／自動證據與使用者驗收分開；PC 優先。手機由 MSW 自動適配仍需基本點按檢查，但不是 M1 關閉的強制前置。 |

## 3. 核心循環

1. 玩家在港口探索並接近自己的船。
2. 只有在有效登船／靠船狀態時，顯示啟航入口。
3. 玩家在官方世界地圖選擇已解鎖目的港；系統計算直線穿越的空域順序、距離與風險，不提供航點或途中改道。
4. 進入甲板開始航程倒數；舊事件與菇菇襲擊停用。新空戰獨立驗收，不沿用舊事件結算。
5. 抵達目的港，回到可探索港口並使用 NPC 商店完成交易。
6. HUD 顯示當前港口、目的地、貨艙／金幣與航行狀態，錯誤狀態可理解且可重試。

## 4. M1 目標與非目標

### 目標

- 建立可被四張港口地圖與甲板共同使用的港口、航線、船體登船點與幾何資料契約。
- 讓世界地圖 UI 的按鈕、目的地狀態與港口資料一致，避免 UI 顯示與實際可達性漂移。
- 對四港 ↔ 甲板流程做可重複的 build/runtime 與 PC 視覺驗收；商品依產地不同，外港收購價較高。

### 非目標

- 不新增四港以外的港口、完整怪物族群、技能、角色升級、技能書商店或離船空戰。
- 不切換任何地圖 TileMapMode，不重畫整張地圖，不重構已完成交易／甲板戰邏輯。
- 不把 Maker 截圖當作玩家 PC／手機實機體驗的替代證據。

## 5. 系統 ↔ MSW 對照

| 系統 | MSW 落點 | M1 注意事項 |
| --- | --- | --- |
| 港口／航線資料 | `@Logic` 的世界狀態 + UserDataSet/CSV（穩定後） | 以唯一港口 id、目的地 id、航線 id 對齊 UI 與傳送。 |
| 港口場景 | `.map`、MapleTile、Foothold、`RigidbodyComponent` | 四港與甲板 root mode 均須為 0；每張圖須保有可走動線與可達登船／商店點。 |
| 船與登船點 | `.map` entity／Transform／CustomFoothold | 只由實作代理修改；M1 文件記錄幾何契約與驗收點。 |
| 世界地圖／HUD | `.ui` + client-only UI runtime | 必須保留既有 UUID，走 UIBuilder；伺服器狀態透過同步資料提供。 |
| 交易 | 四港地方商品、外港收購價與貨艙資料 | 保留可倒賣獲利；不能以港口 `if/else` 寫死價格。 |
| 航行與空戰 | 可調基準航程、船型與卡片倍率、船體結算 | 舊事件停用；新空戰需驗證與抵港競合、一次結算及沉船清貨。 |
| 驗證 | MissionCenter tasks + smoke-tests + 使用者測試 | Done 必須有證據；視覺／手機標為 user-test pending 直到主人確認。 |

## 7. M1 完成定義

- 四港與甲板皆可移動，地圖型別／Body／Foothold 契約沒有漂移。
- 四港可互相直航、抵達、開商店並再次出航；世界地圖只提供合法目的地，箭頭起終點與地標一致。
- 航程以可調基準與倍率推進，HUD 百分比正確；舊事件不再觸發，新空戰／抵港只能結算一次，船損與貨物依成功抵港或沉船規則處理。
- 甲板中繼與既有交易／護船流程回歸通過，無新增 build/runtime 錯誤。
- 有 MissionCenter 對應任務、smoke 證據與明確的使用者 PC 視覺結果；手機基本點按列為後續實機檢查，不冒充已通過。

## 8. 風險與移交

- `Archive/As-built.md` 是 brownfield 基線；若實作前發現地圖／腳本漂移，先更新 As-built 與任務依賴，再動手。
- 任何未列於三個 Phase 的需求先進 `Docs/GreatVoyage-Roadmap.md` Backlog。
- 實作代理只能更新自己負責的 Phase 文件與對應驗證；跨 Phase 依賴需在 MissionCenter 任務備註中留下原因。
